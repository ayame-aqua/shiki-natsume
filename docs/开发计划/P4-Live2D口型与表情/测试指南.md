# P4 Live2D 口型与表情 — 测试指南

## 快速开始

### 环境要求

- Python 3.11+
- 已安装依赖（`pip install -e .`）
- 已配置 `.env` 文件（LLM API、TTS 等）

### 启动服务

```bash
python -m src.main
```

默认监听 `http://127.0.0.1:8787`

## 测试场景

### 场景 1: 未配置模型（默认状态）

**预期行为**：

1. 打开 `http://127.0.0.1:8787`
2. 左侧应显示灰色占位符："未配置模型"
3. 右侧聊天区正常工作
4. 可以正常发送消息、接收回复
5. TTS 语音正常播放（如果已配置）

**验证点**：

- ✅ 页面不崩溃
- ✅ 聊天功能不受影响
- ✅ 控制台输出 "No Live2D model configured"

### 场景 2: 配置模型后

**配置步骤**：

1. 准备一个 Cubism 3–5 模型（需有权使用）
2. 将模型文件放到 `web/live2d/natsume/`
3. 编辑 `web/live2d/model_dict.json`：

```json
[
  {
    "name": "natsume",
    "url": "/live2d/natsume/model.model3.json",
    "kScale": 0.4,
    "emotionMap": {
      "neutral": "idle",
      "happy": "smile",
      "sad": "sad",
      "angry": "angry",
      "shy": "blush"
    }
  }
]
```

4. 刷新页面

**预期行为**：

- ✅ 左侧显示 Live2D 模型
- ✅ 模型处于 idle 状态
- ✅ 每 4 秒眨一次眼
- ✅ 呼吸动画平滑循环

### 场景 3: 口型同步测试

**测试步骤**：

1. 确保已配置 TTS（GPT-SoVITS 或其他）
2. 在聊天框输入消息并发送
3. 等待 Agent 回复
4. 观察 TTS 播放时的口型

**预期行为**：

- ✅ TTS 开始播放时，嘴巴开始张合
- ✅ 嘴巴张合幅度与音量大致对应
- ✅ 音频结束后，嘴巴平滑闭合
- ✅ 没有明显抖动或延迟

**调试**：

- 打开浏览器控制台（F12）
- 查看是否有 "Failed to start lip sync" 错误
- 检查 AudioContext 是否正常初始化

### 场景 4: 表情切换测试

**测试步骤**：

1. 发送多条消息，触发不同的情绪回复
2. 观察 Live2D 表情变化

**预期行为**：

- ✅ 收到 `emotion: "happy"` 时，切换到 smile 表情
- ✅ 收到 `emotion: "sad"` 时，切换到 sad 表情
- ✅ 收到 `emotion: "angry"` 时，切换到 angry 表情
- ✅ 收到 `emotion: "shy"` 时，切换到 blush 表情
- ✅ TTS 结束后约 1.5 秒回到 neutral 表情
- ✅ 连续对话时表情会更新，不会卡死

**触发特定情绪的示例对话**：

- **happy**: "今天天气真好！" / "我考试通过了！"
- **sad**: "我很难过" / "今天心情不太好"
- **angry**: "太气人了" / "真让人生气"
- **shy**: "有点不好意思" / "让你见笑了"

**调试**：

- 控制台应输出 "Emotion changed to: xxx"
- 如果表情不切换，检查 `emotionMap` 配置是否正确
- 如果输出 "Emotion motion not found"，说明模型中没有对应的 motion

### 场景 5: 响应式布局测试

**测试步骤**：

1. 调整浏览器窗口宽度
2. 观察布局变化

**预期行为**：

- ✅ 宽屏（> 900px）：Live2D 在左，聊天在右
- ✅ 窄屏（< 900px）：Live2D 在底部，聊天在上
- ✅ 超窄屏（< 600px）：Live2D 高度减小
- ✅ 所有布局下功能正常

### 场景 6: 降级处理测试

**测试步骤 A: 删除模型文件**

1. 将 `web/live2d/model_dict.json` 改为 `[]`
2. 刷新页面

**预期行为**：

- ✅ 显示"未配置模型"占位符
- ✅ 聊天功能正常
- ✅ 语音功能正常

**测试步骤 B: 模型加载失败**

1. 将 `model_dict.json` 中的 `url` 改为不存在的路径
2. 刷新页面

**预期行为**：

- ✅ 显示"模型加载失败"占位符
- ✅ 控制台输出错误信息
- ✅ 聊天功能不受影响

## 常见问题

### Q: 模型不显示，但控制台没有错误

**排查**：

1. 检查 `model_dict.json` 格式是否正确（JSON 语法）
2. 检查 `url` 路径是否正确（相对于 `/live2d`）
3. 打开 Network 面板，查看模型文件是否成功加载
4. 确认模型是 Cubism 3–5 格式（不支持 Cubism 2）

### Q: 表情不切换

**排查**：

1. 打开控制台，查看是否有 "Emotion mapping missing" 警告
2. 检查 `emotionMap` 的值是否对上 expression 或 motion 组名
3. 打开 `.model3.json`，看 `FileReferences.Expressions` 和 `Motions`
4. 更新 `emotionMap` 使其与模型一致

### Q: 口型不动

**排查**：

1. 确认 TTS 音频正常播放
2. 打开控制台，查看是否有 AudioContext 错误
3. 检查模型是否有 `ParamMouthOpenY` 参数
4. 口型只吃播放链路里的 AnalyserNode；不要对 `<audio>` 调 `startLipSync`

### Q: 音频播放卡顿或口型延迟

**可能原因**：

1. 网络延迟（音频文件较大）
2. 浏览器性能不足
3. TTS 服务响应慢

**解决方案**：

1. 使用本地 TTS 服务
2. 降低 Live2D 模型的复杂度
3. 调整 `web/live2d.js` 中的 `smoothFactor`（默认 0.35）

### Q: Live2D 显示不完整或被裁剪

**解决方案**：

1. 调整 `model_dict.json` 中的 `kScale` 值（0.1–1.0）
2. 修改 `web/live2d.js` 中的 `live2dModel.x` 和 `live2dModel.y` 位置

## 性能调优

### 降低 CPU 占用

1. **减少 idle 动画频率**：修改 `web/live2d.js` 中的 `IDLE_BLINK_INTERVAL_MS` 和 `IDLE_BREATH_INTERVAL_MS`
2. **降低口型采样率**：修改 `analyser.fftSize`（默认 256，可降至 128）
3. **使用更简单的模型**：Cubism 3 模型比 Cubism 4/5 性能更好

### 减少内存占用

1. 使用压缩过的纹理贴图（PNG 转 WebP）
2. 减少模型的 motion 数量
3. 关闭不需要的 idle 动画

## 开发调试

### 在控制台手动测试

```javascript
// 初始化 Live2D
await window.live2d.init();

// 切换表情
window.live2d.setEmotion("happy");
window.live2d.setEmotion("sad");
window.live2d.setEmotion("neutral");

// 口型只吃 AnalyserNode，不要传 <audio>
// 正常路径由 app.js 在 AudioContext 播放时调用 startLipSync
window.live2d.releaseEmotion();

// 手动停止口型同步
window.live2d.stopLipSync();

// 清理资源
window.live2d.cleanup();
```

### 修改配置后的测试流程

1. 修改 `web/live2d.js` 或 `web/live2d/model_dict.json`
2. 刷新页面（Ctrl+Shift+R 强制刷新）
3. 观察控制台输出
4. 验证功能
